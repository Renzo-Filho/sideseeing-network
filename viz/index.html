The objective

A descriptive search for comparable places

The project characterizes the urban form and function of São Paulo's districts, starting from Brás (SP:10), a dense, older central district of retail and garment workshops, and asks which Chicago Community Areas remain comparable once both cities are measured the same way. The comparable places will later anchor a separate study of pedestrian accessibility. Similarity here is descriptive: it selects places to compare, and it does not explain or predict pedestrian outcomes.

The tool turns the project's notebooks into one interface. The notebooks fixed Brás as the reference; here any of the units can be the reference, and every ranking, map, profile, principal-component plot and cluster is recomputed in your browser from the frozen model inputs. A check script reproduces the published results from the same code (analysis/tests/check_viz_model.js).

Three methods

Three definitions of "alike"

Cross-City Urban Index A

One number from six counts

The advisor's sketch. Commerce, dwellings, transit stops, building height, street segments and street length per unit, each min–max scaled over the 173 units and summed. Two places are alike when their totals are close.

\(I_A(u)=C'+R'+H'+V'+N'+L' \in [0,6]\)

Counts grow with the size of the unit, so the index partly measures area (test T1: 0 of 29 merged units consistent).

Cross-City Urban Index B

The same sketch, per km² of land

Counts are divided by land area and height comes from one satellite source for both cities. Scaling and weights are unchanged, so B isolates the effect of those two corrections.

\(I_B(u)=\sum_f \big(f/\text{Land}\big)'\)

Boundary-invariant (T1 passed); still one number, so different mixes can reach the same total.

Harmonized cross-city similarity model

Twenty measurements, one calibrated distance

columns in feature families, each validated in both cities, put on a common scale (hybrid C6) and combined with equal family budgets. Two places are alike when their whole profile is close.

\(D=\sqrt{\sum_b w_b\,m_b/\beta_b}\)

The project's primary model (sp_chicago_model_v2, fitted 8 October 2026: v1 plus the U1 commerce land share).

Documentation · Cross-City Urban Index A

Index A: the advisor's composite index, built as specified

Protocol P-AB-1 (docs/SIMPLE_INDEX.md), decided 1 October 2026. Built by analysis/scripts/build_simple_index_ab.py; step-by-step notebook analysis/simple_index_ab.ipynb; results in analysis/results/SP_CHI/simple_index_ab_2026_10_01/.

The idea

Describe every unit by six factors, two groups of urban intensity, and add them into one number:

\[\text{built environment}=C+R+H+V,\qquad \text{network}=N+L,\qquad I=\text{built environment}+\text{network}.\]

The units are the São Paulo districts and the Chicago Community Areas, pooled into one set of . With equal weights the built environment is 4/6 of the index and the network 2/6.

The six factors

Formulas

\(u\) is a reporting unit (a São Paulo district or a Chicago Community Area); \(\mathbf 1[\cdot]\) is 1 when the condition holds and 0 otherwise.

C · commercial establishments

\[C(u)=\sum_{p\in P}\mathbf 1\big[p\in u\ \wedge\ k(p)\in K\big]\]

\(P\) = all Overture places (release 2026-08-19.0); \(k(p)\) = the top level of the place's taxonomy; \(K\) = {shopping, food_and_drink, services_and_business, lifestyle_services, lodging}. No filter on operating status or confidence, so both cities follow one rule (decision D2).

R · residential establishments (dwellings)

\[R_{\text{SP}}(u)=\sum_{d\in \mathcal D}\mathbf 1[d\in u],\qquad R_{\text{CHI}}(u)=\sum_{b} HU_b\,\frac{|b\cap u|}{|b|}\]

\(\mathcal D\) = IBGE CNEFE 2022 private dwellings; \(HU_b\) = Census 2020 housing units of block \(b\); \(|\cdot|\) = area, so a block cut by a unit boundary is split by area share.

H · transportation hubs

\[H(u)=S(u)+B(u),\qquad S(u)=\sum_s \mathbf 1[s\in u],\qquad B(u)=\sum_t \mathbf 1[t\in u]\]

\(s\) = a metro or 'L' station (CTA parent stations; São Paulo metro stops grouped by name; CPTM excluded because Chicago's feed has no Metra); \(t\) = a bus stop as listed in the GTFS feed.

V · building height

\[V(u)=\frac{1}{n_u}\sum_{k=1}^{n_u} h_k,\qquad h_k>0\]

\(h_k\) = Overture height of building \(k\) (m); a building belongs to the unit that contains its bounding-box centre. Heights come mostly from USGS LiDAR in Chicago and from OpenStreetMap tags in São Paulo.

N · number of streets and L · average street length

\[N(u)=\sum_s \mathbf 1\big[m(s)\in u\big],\qquad L(u)=\frac{1}{N(u)}\sum_{s:\,m(s)\in u}\ell(s)\]

\(s\) = an Overture road segment in the ten street classes, counted as the source cuts it; \(m(s)\) = its midpoint, so each segment counts whole in one unit; \(\ell(s)\) = its length. L enters the index positively, as specified, although longer segments usually mean a coarser network.

Scaling and the index

\[x'(u)=\frac{x(u)-\min_v x(v)}{\max_v x(v)-\min_v x(v)}\in[0,1],\qquad I(u)=C'+R'+H'+V'+N'+L'\in[0,6]\]

The minimum and maximum run over all units pooled, so one extreme unit sets each scale.

From an index to similarity

The agreed rule ranks units by how close their index is to the reference's. The explorer generalizes the sum to adjustable weights \(w_f\ge 0\) (all equal to 1 reproduces the protocol):

\[I_w(u)=\sum_f w_f\,f'(u),\qquad \operatorname{gap}(u,r)=\big|I_w(u)-I_w(r)\big|,\qquad u^*=\arg\min_{u}\operatorname{gap}(u,r).\]

A one-number index can match a total built from a very different mix. The protocol therefore reports a diagnostic, the factor profile distance, which compares the six scaled factors one by one:

\[d(u,r)=\sqrt{\sum_f w_f\,\big(f'(u)-f'(r)\big)^2}.\]

In the explorer the similarity rule switch chooses between the two. The principal components and clusters always use the factor profile, because a single number has only one dimension: PCA of the weighted factors \(\sqrt{w_f}\,f'\) and Ward clustering on its components.

The explorer's "what drives each match" matrix shows, for the gap rule, each factor's signed part \(w_f\,(f'(u)-f'(r))\) of the index difference: a pair with a small gap can hide large opposite differences that cancel.

Pipeline

  1. Acquire. Fetch each source and record its version and SHA-256: Overture 2026-08-19.0 (places, buildings, segments), CNEFE 2022, Census 2020 blocks, CTA and SPTrans GTFS.
  2. Filter. Keep what each factor defines: five place categories; private dwellings; height > 0; ten street classes.
  3. Locate. Assign each record to one unit: point in polygon (places, stops), bounding-box centre (buildings), midpoint (segments), block area share (Chicago dwellings).
  4. Aggregate. One value per unit and factor: counts for C, R, H, N; means for V and L, kept as additive sums so merged units recombine exactly.
  5. Scale. Min–max over the units pooled.
  6. Sum. Equal weights, six factors, index from 0 to 6.

Twenty construction checks guard the build and any failure stops the run: commercial counts by two independent point-in-polygon routes; dwellings conserved against the CNEFE and Census totals; buildings with height reconciled with the source audit; every scaled factor spanning exactly 0 to 1; the index equal to the sum of its factors.

Supported conclusion: Index A is biased as a measure of urban intensity because it sums counts over units of unequal land area. The bias is structural and would remain with perfect data. A high A value means "much commerce, housing, stops and streets inside this boundary", not "a dense place".

Index B tries to show that Index A's ranking reflects unit size rather than urban intensity, and to fix it by putting every factor on a per-area basis, so that redrawing boundaries no longer changes it.

Formulas

\[\operatorname{Land}(u)=|u|-|W\cap u|,\qquad C_B=\frac{C}{\operatorname{Land}},\quad R_B=\frac{R}{\operatorname{Land}},\quad H_B=\frac{H}{\operatorname{Land}},\quad N_B=\frac{N}{\operatorname{Land}},\quad L_B=L\]
\[V_B(u)=\frac{\sum_c w_c\,\mathrm{AGBH}_c}{\sum_c w_c\,\mathrm{AGBH}_c/\mathrm{ANBH}_c},\qquad I_B(u)=\sum_f f_B'(u)\]

\(W\) = municipal hydrography (rivers, reservoirs, Lake Michigan); \(c\) = a GHSL 100 m cell and \(w_c\) its area inside \(u\); AGBH = built volume per cell area; ANBH = built volume per built surface (GHSL R2023A, height epoch 2018). \(V_B\) is the unit's built volume divided by its built surface: the mean height of what is built. Each \(f_B'\) is min–max scaled as in Index A. The similarity rules (index gap and factor profile) are the same as Index A's.

Why per km² removes the boundary effect

Test T1 merges São Paulo's districts into their subprefeituras and asks whether a merged unit's value stays within the range of its parts. For a count the answer is always no, and for a ratio of sums always yes:

\[x_{\text{merged}}=\sum_i x_i\ \ge\ \max_i x_i,\qquad \frac{\sum_i a_i}{\sum_i b_i}=\sum_i \frac{b_i}{\sum_j b_j}\cdot\frac{a_i}{b_i}\ \in\ \Big[\min_i \tfrac{a_i}{b_i},\ \max_i \tfrac{a_i}{b_i}\Big].\]

A merged count is the sum of its parts, so it exceeds the largest part whenever two parts are positive. A ratio of sums is a weighted average of the parts' ratios, so it stays between them. The data confirm the algebra and measure its size (T1 below).

Pipeline

Steps 1 to 6 are those of Index A, with the same records, assignment rules and checks, in one run that builds both indices. Two inputs are added:

  • Land per unit: unit area minus municipal hydrography.
  • GHSL height recombined from built volume and built surface; the recombination reproduces the stored values (relative difference below 1e-9).

What the comparison supports. Index A is biased as a measure of intensity: its count factors and index depend on how boundaries are drawn and rise with unit size. Index B removes that bias: every factor and the index pass T1, and the index does not grow with unit size across the pooled units. Application: the Chicago area closest to Brás

Profile rank = position among the 77 Chicago areas by six-factor profile distance to Brás (1 = most alike). Index A's pick matches Brás's total with a different mix; Index B's pick also ranks among the closer profiles. Neither is a validated analogue: one number cannot hold six dimensions.

The harmonized cross-city similarity model

Contract analysis/config/sp_chicago_model_v2.json, frozen and fitted on 8 October 2026. It is sp_chicago_model_v1 (6 October 2026, kept unchanged) with the U1 commerce land share added by user decision. Code analysis/scripts/sp_chicago_model.py (reusing chicago_model.py); notebook analysis/sp_chicago_model_analysis.ipynb; report docs/harmonization/MODEL_REPORT.md (§11 for v2).

What changed in v2. U1 compares four land-use shares instead of three: residential, commerce, industrial and institutional. The commerce share had failed the J-3 admission rule because it overlaps U6 activity intensity (Spearman 0.708 in São Paulo, 0.445 in Chicago). The user added it on 8 October 2026 because commercial land is central to Brás's profile: 65% of its occupied land, 3rd of 94 São Paulo districts. The overlap is accepted and reported. Setting the commerce weight to 0 in the explorer reproduces v1 exactly.

The question

Which Chicago Community Areas most resemble a given São Paulo district, and the reverse? The model places all units in one space built from measurements in feature families, measures the dissimilarity between every pair, and ranks the units by their distance to a reference. The published report uses Brás; the explorer lets any unit be the reference. The model is target-free: rankings around a reference are read from the full matrix.

The features

The same twelve families as the Chicago model, built with the same definitions in both cities. Each family was accepted step by step, with checks fixed before its results were seen.

Missing: all four U1 shares for O'Hare, Marsilac and Parelheiros (under 10% classified land). Pairs involving them use the families both units have.

The columns as the distance sees them

Putting two cities on one scale (convention C6)

Absolute comparison is right when a number means the same thing in both cities; relative comparison is the safe choice when the measuring instrument differs.

Every transformed column \(t\) is standardized and capped at ±3:

\[z=\operatorname{clip}\Big(\frac{t-\bar t}{s},\,-3,\,3\Big),\qquad s=\sqrt{\tfrac1n\sum (t-\bar t)^2}.\]
  • Absolute: \(\bar t\) and \(s\) over all units (levels compared as measured).
  • Relative: \(\bar t\) and \(s\) within the unit's own city (a unit is compared by its position in its city).
  • Hybrid (primary): absolute for the same-instrument families (M1, M3, M4, M6, M7, B1, U3), relative for the rest (BV, U2, U4, U6, U1).
  • All-absolute and all-relative apply one rule to every column; they are the two extra runs. Switch between all three in the explorer.

Relative scaling removes a city-wide shift and stretch caused by an instrument. It does not fix an instrument that mis-ranks units inside a city.

How the distance is calculated

1 · Transforms (J-5)

Natural log for strictly positive amounts on a ratio scale (U2, U3, U4, M1, M7, BV height, M4 elongation), so that "twice as dense" is the same step everywhere; identity for shares, indices and log-ratios (B1, M6, M4 compactness, M3, already in ln m², U6, U1).

2 · Composition (U6)

The five activity classes (food & drink, retail, services & offices, making & storing, institutions) are compared with the Aitchison distance, the Euclidean distance between centred log-ratios, left unscaled because standardizing log-ratios one by one breaks their geometry:

\[\operatorname{clr}_k=\ln(n_k+0.5)-\frac15\sum_{j=1}^{5}\ln(n_j+0.5).\]

In hybrid and all-relative scaling the log-ratios are centred within each city; all-absolute uses the raw log-ratios.

3 · Blocks and calibration (J-7)

Each family is one block (U6 is two, intensity and composition, each with half of U6's budget). For block \(b\) with \(c_b\) columns:

\[m_b(d,e)=\frac{\sum_{j=1}^{c_b} v_j\,\big(x_{dj}-x_{ej}\big)^2}{\sum_{j=1}^{c_b} v_j},\qquad \beta_b=\operatorname*{median}_{d<e,\ m_b(d,e)>0} m_b(d,e).\]

\(v_j\) = the weight of column \(j\) inside its family. The published model uses \(v_j = 1\), a plain mean, so U1's four shares each get a quarter of the U1 budget. The explorer's "Inside U1" and "Inside M4" sliders change \(v_j\); \(\beta_b\) is then recomputed on the reweighted block. The family weight \(w_f\) therefore sets how much the family counts against the others, and \(v_j\) only sets the mix inside it. A column with \(v_j = 0\) leaves the model, which is how R3 drops one share of a family.

Averaging over columns keeps a three-column family from counting three times; dividing by \(\beta_b\), its median over all 14,878 pairs, puts every block on a common scale.

4 · Distance (J-7, J-8)

\[D(d,e)=\sqrt{\frac{\sum_{b} w_{f(b)}\,s_b\,m_b(d,e)/\beta_b}{\sum_{b\ \text{available for}\ d,e} w_{f(b)}\,s_b}}\]

\(w_f\) = the family budget (equal, 1/12, in the published model; set by the weight sliders in the explorer); \(s_b\) = the block's share of its family. The denominator is 1 except for pairs involving a unit without U1, which use the families both units have.

5 · What drives a match

Each family's part of the squared distance is additive:

\[D^2(d,e)=\sum_f \underbrace{\frac{w_f\sum_{b\in f}s_b\,m_b(d,e)/\beta_b}{\sum_{b\ \text{avail.}}w_{f(b)}\,s_b}}_{\text{part of family } f},\qquad \text{share}_f=\frac{\text{part}_f}{D^2}.\]

The explorer's contribution matrix shows these shares for every top-10 match.

Equal budgets equalize families on a typical pair, not on every pair. Block size (M3) is nearly uniform inside each city's grid and extreme in a few industrial and airport units, so its median pair is small and it carries far more than its nominal 1/12 on average (table below). Lower its weight in the explorer to see how much a ranking depends on it.

Three runs

  • R1, equal weights. The distance above with \(w_f=1/12\).
  • R2, PCA weights. Euclidean distance on the principal components that explain at least 90% of the variance: \(D_{R2}(d,e)=\lVert \mathbf p_d^{(k)}-\mathbf p_e^{(k)}\rVert\), \(k=\min\{k:\sum_{i\le k}\lambda_i/\sum_i\lambda_i\ge 0.9\}\).
  • R3, without correlated features. Scalar columns are dropped while any pair has |Spearman ρ| ≥ 0.70 on the scaled values (most such pairs first; ties to the higher mean |ρ|, then the later position). Under hybrid scaling this drops .

The explorer's run presets set these exactly; the check script reproduces all nine published scaling × run matrices to within 1e-10.

Principal components and clusters

The model has an exact Euclidean embedding, so principal components come from the distance matrix itself (principal-coordinate analysis, identical to PCA of the embedding when no value is missing):

\[B=-\tfrac12\,J\,D^{(2)}J,\qquad J=I-\tfrac1n\mathbf 1\mathbf 1^\top,\qquad B=V\Lambda V^\top,\qquad P=V_{+}\Lambda_{+}^{1/2}.\]

\(D^{(2)}\) = the matrix of squared distances; \(V_+, \Lambda_+\) = the eigenvectors and eigenvalues with \(\lambda>0\). Loadings are the correlations of each component with each model column.

Ward clustering runs on all positive components. At each step it merges the two clusters whose union increases the within-cluster sum of squares least,

\[\Delta(A,B)=\frac{n_A n_B}{n_A+n_B}\,\lVert \bar{\mathbf p}_A-\bar{\mathbf p}_B\rVert^2,\]

and the number of clusters is the \(k\in\{3,\dots,8\}\) with the best mean silhouette \(s(i)=\frac{b(i)-a(i)}{\max\{a(i),b(i)\}}\), where \(a(i)\) is unit \(i\)'s mean distance to its own cluster and \(b(i)\) to the nearest other cluster. Clusters are a descriptive check, not a validated typology.

Pipeline

  1. Accept each family. Freeze its definition, approve numeric checks before seeing results, build it with one script into one dated results folder, sign an acceptance record. A failed check stays recorded as failed.
  2. Joint review (J-1 to J-10). U1 land-share admission (J-3), redundancy merge rule (J-4), transforms, scaling, budgets, missing data and sensitivities, all fixed before any distance was computed.
  3. Freeze the contract. Columns, transforms, scaling, budgets and every input table's SHA-256; inputs are refused if a hash differs.
  4. Cross-city design (X-1 to X-9). 173 units, the C6 hybrid scaling and its two variants, the three runs, fixed before any cross-city value was computed.
  5. Fit once and report R1–R3 under three scalings, PCA, Ward clusters, 500 weight draws and the pre-registered sensitivities.
  6. Export to the explorer. analysis/scripts/export_viz_data.py writes the model's blocks for each scaling; analysis/tests/check_viz_model.js asserts that the browser reproduces the published results.

Limits

  • No external truth. The model describes; no outcome validates similarity itself. Evidence comes from each family's checks, face validity and the robustness tables.
  • The scaling choice is a modelling decision, not a finding.
  • Block size (M3) weighs more than its budget, and drives PC1.
  • The ±3 cap compresses extremes (the Loop on jobs, height and transit; Marsilac on several columns).
  • Relative scaling keeps within-city instrument errors: RAIS head-office registration, LODES location error, Overture's formal-economy bias, GHSL's compression of tall buildings.
  • Vintages differ: Overture 2026, Census 2022 and ACS 2020–2024, RAIS 2022 and LODES 2023, IPTU 2026 and CMAP 2023, GHSL 2018.
