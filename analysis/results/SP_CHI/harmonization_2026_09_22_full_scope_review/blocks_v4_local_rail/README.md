# City-local rail envelope validation

`analysis/scripts/review_local_rail_envelopes_v1.py` adds local polygon boundaries to the no-link block pilots as **city-specific validation only**. Chicago uses 3,024 CMAP Land Use Inventory polygons coded 1511. CMAP's [field guide](https://cmap-repos.github.io/LUI-wiki/1500_TransportationCommunicationsUtilities.html) calls these rail right-of-way parcels and distinguishes them from rail stations/parking. São Paulo's supplied `area_influencia_trem.gpkg` has 12 polygons labelled *área de influência/faixa de domínio CPTM*, which does not establish the same exact right-of-way scope. Their geometry and legal/functional meaning are not assumed equivalent.

After adding each mask's outer boundary and removing polygons with majority mask area, local-reference IoU≥.50 changes only modestly in Chicago: CHI:30 reference match .149→.169, CHI:32 .397→.399, CHI:28 .534→.528. In Brás it worsens candidate match .690→.633 and reference match .915→.902, with four narrow enclosures. The [eight-unit table](paired_local_rail_envelope_sensitivity.csv) and saved candidate polygons retain all comparisons. Local polygons therefore provide inspection evidence, not a shared M3/M4 input or a proven correction to the rail-centerline artifact. A matched physical right-of-way definition remains open.
